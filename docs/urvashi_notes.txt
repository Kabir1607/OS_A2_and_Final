EXTENSIVE EXPLANATION:

8. VIVA GLOSSARY: BASIC TERMS AND PROCESSES
-------------------------------------------

8.1 Project stages

- Smart Library: one simulator for A1 process management, A2 memory
  management, and the Final concurrency/deadlock project.
- A1: readers are processes-like jobs and two librarians are processors.
- A2: adds six contiguous reading seats and first/best/worst-fit allocation.
- Final: adds named shared resources, real Python threads, locking, tracing,
  deadlock detection, and ROLLBACK/ORDERED prevention.

The `.pyi` file is the source of truth. Its signatures and contract rules
must not be changed without team agreement. One module owns one area:
scheduling, memory, engine coordination, resources, workers, deadlocks,
metrics, output, or CLI.


8.2 Reader terminology

- ReaderSpec: immutable input data: ID, arrival, priority, service, category,
  seat requirement, and table requirement.
- Reader: mutable runtime state owned by the engine coordinator.
- ReaderResult: immutable timestamps for a completed reader: ID, A, priority,
  B, S, C, M, and resource wait.
- A: arrival time.
- M: memory-seat admission time.
- S: first librarian dispatch time, even if the reader immediately blocks on
  a resource at offset zero.
- C: completion time.
- B: total service units.
- W: waiting = C-A-B.
- Resource wait: virtual time in BLOCKED_RESOURCE.


8.3 Reader states

A reader state describes its lifecycle, not the data structure it is stored
in.

- NEW: created, not yet arrived or admitted.
- BLOCKED_MEMORY: has arrived but is waiting for contiguous seats.
- READY: has seats and is waiting for a librarian.
- RUNNING: holds a librarian and is executing/allowed to execute.
- BLOCKED_RESOURCE: holds seats but has voluntarily given up its librarian
  while waiting for resources.
- TERMINATED: completed; its seat and librarian are released.

Legally, transitions are:

    NEW -> BLOCKED_MEMORY or READY
    BLOCKED_MEMORY -> READY
    READY -> RUNNING
    RUNNING -> BLOCKED_RESOURCE or TERMINATED
    BLOCKED_RESOURCE -> READY

Every change must use Reader.transition(). This method uses
LEGAL_TRANSITIONS and raises AssertionError for an illegal state change.
For example, READY -> TERMINATED is illegal because a reader must run before
completion.


8.4 ReadyQueue

- ReadyQueue is a heap-based priority queue of memory-admitted readers.
- It belongs to scheduling. It contains readers with seats, not necessarily
  running readers.
- FCFS key: (arrival, id). EARLIER arrival wins; plain-string ID breaks ties.
- PRIORITY key: (priority, arrival, id). Smaller priority number is more
  important.
- "R10" sorts before "R2" because IDs are compared as strings.
- ReadyQueue.pop() chooses the next reader for an idle librarian.
- A reader returning from a resource block keeps its original arrival key,
  rather than gaining priority from the later wake-up.
- The engine is the only coordinator allowed to push/pop it.


8.5 SeatPool

- SeatPool represents six physical reading-seat slots.
- Each slot contains a reader ID or is empty/None.
- It does not decide FIFO admission order. That is AdmissionQueue's role.
- It also does not choose which READY reader gets a librarian.
- allocate(reader_id, k) finds k contiguous seats using the selected allocator.
- FIRST_FIT chooses the first run large enough.
- BEST_FIT chooses the smallest fitting run, with lowest start as tie-break.
- WORST_FIT chooses the largest fitting run, with lowest start as tie-break.
- release(reader_id) frees exactly that reader's slots and coalesces adjacent
  free runs.
- occupied is the current number of occupied seats.
- largest_free_run is the longest contiguous empty segment.
- external fragmentation is total free seats minus largest_free_run.
- capacity may be larger in tests for A1 cross-checking, but graded A2 uses 6.
- The pool must never allocate overlapping seats or exceed capacity.


8.6 AdmissionQueue

- AdmissionQueue is the strict FIFO waiting queue for memory-blocked readers.
- Reader arrival does not bypass the queue.
- admission is stopped by the head. If the head request cannot fit, no later
  smaller reader may bypass it. This is head-of-line blocking.
- admit_ready() loops until the head fits and is admitted or the queue is
  empty. It never drops a reader.
- On successful admission, M is set to virtual time t and the reader changes
  from BLOCKED_MEMORY to READY.
- Example: R1 requests 4, R2 requests 3, R3 requests 1. R3 can remain blocked
  behind R1/R2 even if its own single seat could fit elsewhere.
- A new BLOCKED_MEMORY reader emits BLOCK_MEMORY tracing in Final mode.


8.7 OccupancyTracker

- OccupancyTracker collects seat statistics from SeatPool.
- It is called once per processed virtual timestamp, after all repeated
  steps at that timestamp have finished.
- It must not be called after each arrival/admission microstep.
- The sampled occupancy holds until the next sample.
- peak_occupied is the maximum occupied count.
- occupied_integral is sum(occupied seats * elapsed virtual interval).
- max_ext_frag is the maximum external-fragmentation value seen.
- PoolStats contains name, capacity, peak, integral, max fragmentation,
  start time, end time, and utilization_pct.
- utilization_pct = occupied_integral / (capacity * (end_time-start_time)) * 100.
- PoolStats already returns a percentage; output.py only formats it.


8.8 Librarians and dispatch

- NUM_LIBRARIANS is 2.
- Both librarians are identical for scheduling purposes.
- When both are free simultaneously, fill librarian 0 before librarian 1.
- Dispatch means READY -> RUNNING. S is set here on the first dispatch.
- Non-preemptive means a RUNNING reader keeps its librarian and is not
  interrupted merely because a higher-priority reader arrives.
- In A2, dispatch reserves a full remaining service burst.
- In Final mode, a RUNNING reader can voluntarily give up its librarian by
  entering BLOCKED_RESOURCE for an ACQUIRE.
- A completion or resource block releases the librarian.
- Seat release happens only at completion, not on resource blocking.


8.9 Virtual time

- Virtual time is the logical integer clock of the simulation.
- It is not real wall-clock elapsed time and is not measured in seconds.
- It starts at the earliest arrival time found in the input. If the earliest
  arrival is 0, virtual time starts at 0. There is no rule forcing it to be 0
  regardless of input.
- Examples of virtual-time values:
  - arrival A;
  - memory admission M;
  - start S;
  - completion C;
  - resource work offset;
  - time blocked for a resource.
- Idle gaps are skipped. The engine jumps to the next arrival/completion/
  resource action rather than incrementing one unit at a time.
- At a timestamp, all changes are drained before the clock advances.
- The clock ends when every reader is TERMINATED, or when no future event
  exists and unfinished readers cannot progress.
- Normal end C is a reader completion timestamp, not a fixed configured limit.
- In incomplete-resource runs, the engine uses find_cycles() and stops.
- Virtual time controls the graded timestamps and output numbers.


8.10 Wall-clock time

- Wall-clock/performance time is real elapsed Python/process time.
- The engine imports perf_counter and measures run() duration around the
  simulation.
- It is stored in SimulationResult.wall_time_s.
- --stats may print it to stderr; it must never enter graded output.
- Wall time is useful for measuring worker synchronization overhead and
  comparing policies over repeated runs.
- Wall time is not used to decide virtual arrivals or completions.
- A virtual C of 100 might be simulated in 0.01 real seconds.
- A virtual C of 10 might take 2 real seconds if worker thread coordination
  is slow.
- Final threads provide concurrency; no sleep is used for virtual blocking.


8.11 Discrete-event loop

The contract intends this order; current Final wake processing happens
inside the action round before completions (documented deviation):

1. due resource actions;
2. completions by ascending ID;
3. arrivals by ascending ID;
4. FIFO memory admission;
5. resource-woken readers become READY;
6. idle librarians are filled;
7. actions due immediately after dispatch.

Steps are repeated until no change remains at t. Then occupancy is sampled.
The clock advances to the minimum next arrival/completion/action time.

This order is important. A completion and arrival at equal t must process in
completion-first order; the released seat can then admit the arrival.
No future event at t is allowed to leak into t+1 processing early.


8.12 Lifecycle timestamps and metrics

- mem_admit: set when the AdmissionQueue actually allocates seats.
- start: set only the first time READY -> RUNNING occurs.
- completion: set only RUNNING -> TERMINATED.
- mem_wait: M-A.
- response: S-A.
- turnaround: C-A.
- waiting: C-A-B.
- ready_wait: waiting-mem_wait-resource_wait.
- throughput: N/E, where E=max C-min A.
- service utilization: sum(B)/(2E)*100 for two librarians.
- average memory wait: mean(M-A).
- blocked_for_memory_count: readers with M>A.
- Metrics asserts A<=M<=S<=C and WAITING=MEM_WAIT+READY_WAIT+RESOURCE_WAIT.


8.13 ResourceManager and worker concepts

- ResourceSpec: resource ID and capacity 1 in this Library.
- STANDARD_RESOURCES: 17 named resources.
- Action: reader ID, work offset, ACQUIRE/RELEASE, resource ID, units, and
  stable row index.
- work_offset: units of service completed when the action is due.
- ActionBatch: all actions for one reader at one current offset.
- WorkerPool: submits batches to real threads and joins futures.
- BatchResult: done count, blocked flag, woken readers, and thread name.
- done: successful actions in that batch.
- blocked: the batch stopped at an ACQUIRE that returned BLOCKED.
- woken: readers that now own everything granted by releases/rollbacks.

Worker threads touch shared resource state only through Samar's locked
ResourceManager and Tracer. They do not directly mutate Reader, ReadyQueue,
SeatPool, or AdmissionQueue. The GIL does not make multi-step resource logic
atomic, so locks remain necessary.


8.14 ACTION pointer rules

- executed: service units completed so far.
- next_action: index of the next action not yet completed.
- dispatched_at: current dispatch virtual time.
- executed_at_dispatch: executed at that dispatch.
- next action time: dispatched_at+(work_offset-executed_at_dispatch).
- After a batch, next_action += done.
- If an ACQUIRE blocks, that ACQUIRE stays at next_action and is not done.
- It is never re-run after wake-up; re-running it would be a double acquire.
- On wake, next_action += 1 because the reader already owns that resource.
- A rollback may give a reader resources back. The work offset does not rewind.


8.15 Blocked and woken processing

For one worker round:

1. Apply all done and blocked results.
2. For every blocked reader:
   - state -> BLOCKED_RESOURCE;
   - set blocked_since=t;
   - free its librarian;
   - keep its seat.
3. Only after blocked results are applied, process the union of woken lists.
4. A woken reader must be BLOCKED_RESOURCE.
5. It becomes READY and receives resource_wait += t-blocked_since.
6. Queue it in ReadyQueue.

If a reader blocks and is woken in the same worker round, it ends READY with
no resource wait added for that round.


8.16 Concurrency and synchronization

- Concurrency: multiple tasks can make progress over overlapping time.
- Parallelism: simultaneous execution on hardware. Python GIL can limit CPU
  parallelism even though threads remain concurrent.
- Lock: mutual exclusion protecting a critical section.
- Critical section: check and update of shared state must occur together.
- Race: multiple threads read/update ownership in a conflicting interleaving.
- Exclusivity: capacity-one resources must never have multiple holders.
- Trace audit: independently replay ownership events to verify resource
  exclusivity and illegal release behavior.
- Engine exclusivity result: max(ResourceManager count, trace audit count).
- no busy waiting: workers do not loop checking for free resources.
- no polling sleep: virtual blocking replaces sleeping for correctness.


8.17 Deadlock concepts

- Wait-for graph: maps a blocked reader to readers holding required resources.
- Cycle: a reader waits on a chain that returns to itself.
- NONE: unsafe demonstration policy. A blocked reader can hold resources.
- ROLLBACK:
  if an acquire is busy and the reader holds resources, it gives up holdings
  and waits for the needed set atomically.
- ORDERED:
  resources have a global rank. The invariant prevents a reader from waiting
  on a lower-ranked resource than its holdings.
- find_cycles(wait_for_graph): returns deterministic wait-for cycles.
- Unresolved deadlocks: count of cycles found after no future event remains.
- No-hang guarantee: stop and report rather than spin forever.
- A2 zip never needs NONE/ROLLBACK/ORDERED classes.

8.19 Trace and policy statistics

- TraceEvent: sequence number, virtual t, event kind, reader, resource,
  thread name, and detail.
- Engine emits ARRIVE, BLOCK_MEMORY, ADMIT, DISPATCH, UNBLOCK, COMPLETE,
  and DEADLOCK.
- ResourceManager emits ACQUIRE, BLOCK, RELEASE, HANDOFF, and ROLLBACK.
- Traces are human-readable and written outside graded output.
- PolicyStats contains policy, rollbacks, resources rolled back,
  reacquisitions, out-of-order requests, and held-while-waiting count.
- wall_time_s is also diagnostic, not graded output.


8.20 Output contract

- Input/output text is UTF-8.
- Output lines use LF/newline, no header, no prose, and no blank rows.
- A2: PROCESS lines sorted by ID, eight SUMMARY lines, then POOL.
- Final: A2 PROCESS lines plus RESOURCE_WAIT, SUMMARY, POOL, RESOURCE lines
  sorted by ID, and three CHECK lines.
- Every decimal in A2/Final uses exactly four decimal places.
- A1 uses the original six-place C++ format.
- write_output() writes the file with newline="\n".

8.23 Common viva distinctions

- ReadyQueue: READY/seat-admitted readers waiting for librarians.
- AdmissionQueue: memory-blocked arrived readers waiting for seats.
- SeatPool: the physical seat allocation state.
- ReadyQueue is scheduling; AdmissionQueue is memory admission.
- Virtual time: simulation timestamps and metrics.
- Wall-clock time: real process synchronization/experiment overhead.
- Reader state: lifecycle phase.
- Queue/pool: location or ownership structure; neither replaces state.
- Deadlock: circular wait after no resource progress remains.
- Rollback: breaks hold-and-wait; holds can be released.
- Ordered: breaks circular-wait using ranked resources.
- Coordinator: one thread owns virtual clock, Reader, ReadyQueue, SeatPool,
  and AdmissionQueue.
- Workers: operate resource ownership through locked managers only.
