1. WHERE THE CODE IS
--------------------
  src/library_sim/     errors, models, scheduler, parser, metrics, output, a1
  tests/contract/      one contract test file per module
  tests/integration/   cross-module tests (all modules now exist, so they all run)
  tests/fakes/         put your shared fakes here (see tests/fakes/README.md)
  docs/readme/         README sections (mine are there, add yours)

Put YOUR module in src/library_sim/ too (memory.py, engine.py,
resources.py, ...). Use relative imports inside the package:

    from .models import ReaderSpec, State
    from .errors import InputError

Why src/: a library_sim/ folder next to library_sim.pyi would be shadowed
by the stub in VS Code / Pylance / mypy, and imports would show as broken.

To use the package from a script or the REPL, run from the repo root with:

    PYTHONPATH=src python3 your_script.py


2. BEFORE EVERY PR, RUN
-----------------------
    python3 -m unittest discover -s tests -t . -v               # all tests
    python3 -m unittest tests.contract.test_pyi_conformance -v  # does my module match the .pyi?

The conformance test reads library_sim.pyi and checks every module that
exists in src/library_sim/ against it: parameter names and order,
dataclass fields and their order, enum values, properties and constants.
Modules that don't exist yet are skipped. So when you add memory.py, it
immediately tells you if you named something differently from the
contract. (I tested it by breaking things on purpose; it caught every one.)

Everything runs on Python 3.10+, standard library only. Tests use unittest.


3. THE MODULES
--------------
No fakes are needed for my modules: the real ones are finished.

errors.py
    InputError(message, line_no=None): str(e) gives "line 4: SERVICE must be >= 1"
    UsageError(message):                bad command-line arguments
    In the CLI, catch both, print f"Error: {e}" to stderr, return 1, and
    write no output file.

models.py (shared types)
    NUM_LIBRARIANS = 2, SEAT_CAPACITY = 6, STANDARD_RESOURCES (the 17 names)
    Scheduler / Allocator / ActionType: str enums, so Scheduler("FCFS") parses
        a CLI argument (case-sensitive, ValueError if unknown)
    State + LEGAL_TRANSITIONS: the lifecycle table
    ReaderSpec(id, arrival, priority, service, category, space_req=1, table_req=0): frozen
    ResourceSpec(id, capacity)
    Action(reader_id, work_offset, action, resource_id, units, row_index)
    SimulationInput(quantum, readers, resources=(), actions=(), has_resource_section=False)
        .n, .reader(id), .actions_for(id)  (sorted by (offset, row_index))
        readers are in FILE order, not sorted
    Reader(spec, actions=(), ...): mutable runtime state, coordinator thread only
        .transition(new_state) raises AssertionError on an illegal move,
        e.g. NEW -> RUNNING. Use it for EVERY state change.
    ReaderResult(id, arrival, priority, service, start, completion, mem_admit,
                 resource_wait=0): what the engine hands to metrics

scheduler.py
    q = ReadyQueue(Scheduler.PRIORITY)
    q.push(spec)     # ValueError if that ID is already queued
    q.pop()          # best reader by key; IndexError when empty
    q.peek(), len(q), bool(q), "R1" in q
    Keys: FCFS (arrival, id), PRIORITY (priority, arrival, id). IDs compare
    as strings ("R10" < "R2"). A reader coming back from BLOCKED_RESOURCE:
    push its original spec again; it keeps its original arrival time.

parser.py
    inp = parse_file(path, "A2")        # or "FINAL"; also parse_text(text, mode)
    All the spec's validation is done, with line numbers (InputError).
    A2 mode: anything after the reader rows is an error.
    FINAL mode: if more lines follow, it calls Samar's
        resource_parser.parse_resource_sections(lines, start, readers)
    (imported only in that case, so the A2 zip works without the file).

metrics.py
    metrics = compute_process_metrics(results)    # results: list of ReaderResult
    summary = compute_summary(metrics)
    Metrics come out sorted by ID. It ASSERTS A <= M <= S <= C and that no
    waiting component is negative. If it fails, the bug is in whatever
    produced the timestamps (usually the engine), not in metrics.

output.py
    text = format_a2(metrics, summary, pool)
    text = format_final(metrics, summary, pool, resources, checks)
    write_output(output_path, text)              # UTF-8, '\n' line endings
    fmt_decimal(x) -> 4 decimal places (only needed if you print stats yourself)
    output.py only READS these attributes, so they must exist with exactly
    these names (as in the .pyi):
      pool:      name, capacity, peak_occupied, utilization_pct (property), max_ext_frag
      resources: resource_id, capacity, max_simultaneous_holders, acquisitions, wait_events
      checks:    exclusivity_violations, unresolved_deadlocks, completed_count
    It sorts resources by ID itself. Pass [] for no resources; the CHECK
    lines are still written.

a1.py
    The A1 port (byte-identical to the C++ output). run_a1(readers, scheduler)
    is the reference the engine is checked against in K10.
